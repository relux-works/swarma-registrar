# Offline format vectors

The 328 cases instantiate the two-domain table in specification Appendix B.
Registration has 138 negative and 33 positive cases. Enrollment has 130 negative
and 27 positive cases, including ten independent codec controls. Appendix B.1
homeserver integration plans remain separate qualification requirements; these
files do not simulate successful live logins.

`0-negative/` precedes `1-positive/` in each domain. Filenames are the original
row IDs. Each negative names a committed positive control. Run tools from the
repository root:

```sh
GOMAXPROCS=2 go run ./tools/vectorgen
GOMAXPROCS=2 go run ./tools/vectorgen -check
python3 tools/vectorcheck/check.py
```

The generator writes the two domain directories, `keys/seeds.json` and
`keys/public-keys.json`.
Check mode compares every generated byte and refuses missing, changed or extra
vector JSON files. It never rewrites files. The Python checker reads committed
inputs, not generator functions or generated verdict code, and independently
checks exact outcomes and final state. Python dependencies are pinned in
`tools/vectorcheck/requirements.txt`. Neither command contacts a homeserver or
loads deployment keys. See [the test-key provenance](keys/README.md).

Each JSON file contains:

- `row`, `domain`, `claim`, `positive_control` and `mode` identify the contract.
- `input.bytes_base64` contains the exact received bytes, using canonical
  unpadded base64url. This preserves malformed UTF-8, duplicate members,
  lexical numbers, escaping, wire whitespace and byte-count boundaries.
- `fixture` fixes UTC seconds, actual process start in milliseconds, startup and
  current clock health, the immutable barrier, protected registry pins/snapshot,
  nonce cache, monotonic limiter events/capacities, signer and audit inputs.
- `before` and `after` define ordered request, clock, restart and signer events.
  Requests in those traces have their own exact outcomes and deterministic JWTs.
  Request events may include optional `monotonic_now`, a nonnegative integer of
  elapsed whole seconds used for monotonic limiter accounting. When absent,
  that request uses `fixture.monotonic_now`, even if the preceding request supplied
  an override; it does not inherit the preceding request's value.
  Restart clears only volatile accounting, never prior audit or authority.
- `expected.code` is exactly one refusal or `accept`. Side effects are separate
  in `expected.state`: exact authority record IDs/revision, accounting, audit
  outcomes and readiness. JWT successes include exact header, claims, signature
  and compact JWS bytes. PR16 also pins the canonical audit line and its hash.
- Codec-only controls pin exact canonical output. The extraction control retains
  nested `sig` data and omits envelope members by selecting only `body`.

The checker also verifies every derivable envelope hash and raw signature
verdict independently of admission precedence. Malformed CCJ or missing/invalid
encoding fields have no normative hash/signature verdict; their rejection is
checked at the applicable earlier gate.

Registry `files` entries supply signed envelope bytes, paths and entry kinds.
A `repeat` plus `path_template` is an explicit compact fixture for aggregate
bounds: expand actual bytes under distinct paths before counting. No count or
size assertion replaces the underlying byte lengths. Protected `object_format` is explicit (`sha1` or `sha256`); it is never inferred
from `revision`. E115–E130 cover cross-format, width, spelling and configuration
refusals; PE16/PE17 install valid per-format snapshots. `previous_files` and
`previous_revision` fix the last accepted authority for rollback tests.

The independent checker implements strict point/subgroup checks as well as
library signature verification. Focused witnesses additionally distinguish
invalid scalar ranges, valid high-S twins, canonical-but-invalid equations,
small-order/mixed-order points, noncanonical points and the 70-byte DER case.
CCJ negative witnesses must fail the codec itself for their named lexical
reason, rather than merely failing a later schema. Positive cases exercise
both algorithms and allowed noncanonical wire order/escaping. R18/E18 pin
exactly 17 containers; PC3 preserves its inner array order at allowed depth 16.
Leading-hyphen structured-name controls include exact 255/256-byte mxid
boundaries, malformed roles and legacy-only explicit-list neighbors. Media
controls distinguish internal token spaces from unquoted charset case variants.
They also pin accepted SP/HTAB around the charset separator and complete field
value, refusal of whitespace around `=`, and refusal of quoted charset values
under the deliberate RFC 9110 narrowing in specification §6. The dedicated
unquoted charset control differs from its quoted neighbor only in quotation.

Clock verification, Git approval/signature/ancestry results, filesystem entry
kinds, atomic persistence, signer availability, sink acknowledgements and
scheduled operator changes are explicit external fixture inputs. The tools
model their consequences; they do not qualify a clock monitor, Git trust loader,
filesystem, persistence implementation, network sink or service concurrency.
Concurrent nonce fixtures serialize the two atomic reservations and assert one
issuance; actual concurrent service execution remains an integration obligation.
Audit outcome traces are abstract append/ack observations; only PR16 pins full
line bytes. No refusal may return a JWT or discard a reserved nonce. Successful
loader fixtures install exactly the candidate authority; rejected candidates
retain previous authority and fence readiness.

To test a checker, copy `vectors/` to scratch, plant a single defect there, and
use `go run ./tools/vectorgen -out <copy> -check` or
`python3 tools/vectorcheck/check.py --vectors <copy>`. A meaningful control fails
for the planted mismatch, not an import error, missing setup or a crash. Keep
all planted files outside the repository.
